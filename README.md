# 双鱼部落写作业机器人

版本 1.3.2。Windows 桌面助手，通过雷电模拟器的 ADB 和自建无障碍桥接操作 Android 应用 `com.sybl.voiceroom`。

停止后不再被晚到的“停止中”状态重新锁住；按钮依据带版本的后台状态恢复。支持采集中断后关闭新版资料卡，以及从私聊/主页/搜索页返回继续采集。新一轮采集不会混入上一轮指标。

私聊遇到本条新消息明确的“贡献等级不够”拒绝时记失败并继续下一用户；结果不明仍保留待确认。桥接命令在同一次 ADB 往返读取请求专属响应，设备检查短期缓存，中文直接用无障碍输入控件，减少界面等待。保留用户设置的目标间隔。

自动私聊按已采集的已核验 UID 搜索用户，核对主页和聊天对象的 UID 后打开首次或已有会话，按文案编辑页保存的指定/随机文字发送。昵称可选；保存或启动时纳入输入框草稿，启动确认显示实际文案。规则保留已选采集日期、时段和来源。

多房间采集遇到房间密码弹窗会立即返回房间列表，继续尝试其他房间；同一轮跳过已尝试的密码房，并在日志中记录原因。

## 当前能力

| 功能 | 已实现范围 |
| --- | --- |
| 文字私聊 | 查找已有会话，精确匹配昵称，发送前读取对方主页核对 UID |
| 规则 | 房间观察记录或本地名单；日期、性别、已知公会筛选；黑名单、批内去重、每日去重和发送上限 |
| 房间采集 | 多房间遍历、成员列表翻页、可见麦位公开资料卡补全；保存历史记录；仅昵称记录标为未取得 UID |
| 欢迎 | 检测进入事件，尝试可用欢迎入口；入口不存在时跳过 |
| 打call | 点击可用表情入口，记录动作次数；不替换为公屏文字 |
| 结果核对 | 显示界面确认、失败、待确认、模拟和跳过；待确认目标禁止自动重发 |
| 演示 | 在设置页显式选择，不操作真实设备，不写真实统计和去重 |

图片、语音、云端后端、按任意 UID 搜索并新建会话尚未实现。采集用户不等于该用户已有可用会话。采集记录不代表完整在线名单，公会或性别无法读取时保留未知。

## 环境与启动

- Windows、Node.js 20 或以上。
- 雷电模拟器，已安装并登录“双鱼部落”。
- 真实任务需要 SYL Bridge 协议 v2。
- 中文输入依赖已安装、可用的 ADBKeyboard；本项目不会自动下载或安装该第三方输入法。

```powershell
npm ci
npm start
```

也可双击 `start.bat`。`ShuangyuAssistant_DEBUG.bat` 前台显示启动日志，不会终止其他 Electron 应用。脚本相对自身定位，保持 ASCII 与 CRLF。

## 使用步骤

1. 启动模拟器，在模拟器里登录应用。
2. 在本软件设置页选择真实模式，点击检测并连接。未连接时任务会失败并显示原因，不自动回落演示。
3. 升级旧版用户点击“安装/启用无障碍桥接”，安装随软件提供的 v2 APK。只有服务连接且协议握手通过才显示已就绪。
4. 采集房间记录，或在本地列表输入 `UID,完整昵称`。昵称可包含空格和后续逗号；纯 UID 可以先用昵称解析，解析来源仍是已有会话。
5. 配置有效文字文案，关闭旧版遗留的媒体选项，再启动任务。

所有操作型任务互斥，包括私聊、采集、欢迎、打call、昵称解析、桥接安装、重连及模式切换。冲突时提示当前占用者。停止会等待本轮收尾；已发出的动作不能撤回。

## 结果含义

采集面板可选择多房间或单房间，并设置每轮房间、成员页数、资料卡检查数量。默认多房间 12 个、每列表 6 页、每房间最多检查 6 张卡。设资料卡数量为 0 可禁用补全；单房间模式不轮换。

成员列表为空时回退公屏与麦位；资料卡必须精确匹配昵称并显示真实 `tv_user_code` 才补全 UID。同昵称不同房间保留独立未核验线索。缓存只用于减少重复检查，不把后续昵称观察自动当作已核验 UID。

当前房间与扫描状态会实时更新；“本次新发现真实 UID”排除已有历史 UID，不把重复观察或仅昵称记录算作新真实 UID。采集只浏览，不操作私聊、关注、礼物或上麦。

采集参考与实测见 [采集优化报告](docs/采集优化报告.md)。

- **界面确认**：对方 UID 已核对，完整输入正确，发送后出现新的相同文本且输入框清空。这不等于服务器确认送达。
- **待确认**：点击发送后超时、断线、取消或证据不足。停止本批次，保存待确认记录并禁止自动重发。
- **失败**：未进入有效发送流程或明确失败。
- **模拟**：演示操作，不计入真实发送次数。

在控制台点击“核对待确认记录”。先在模拟器中检查对应 UID 的消息，再确认已发送或确定未发送；不确定时取消并继续保留限制。

## 数据保存与升级

配置、来源、观察记录与结果保存在 Electron `userData` 目录。开发运行通常为 `%APPDATA%/shuangyu-assistant/`；隔离开发可指定 `SYBL_USER_DATA_DIR`。

- `config.json`：规则、文案、黑名单、执行模式。
- `records-v2.json`：真实观察历史。
- `outcomes-v2.json`：真实操作结果，是新版统计与去重的依据。
- `.bak`：原子保存时保留的上一个版本。

旧版 `stats.json`、`sent.json` 保留，旧统计可能混有演示结果，因此不自动纳入新版真实统计。旧版 `source.json` 的演示状态不能开启新版演示，必须显式选择执行模式。

发送结果损坏时优先读取备份，并阻止发送，提示用户核对完整记录；两份均损坏时明确提示启动失败并退出。恢复前先复制原始文件和备份，避免丢失待确认记录。不要通过删除结果文件来绕过去重。

## 开发与验证

```powershell
npm run dev
npm test
npm run check
npm run smoke
npm run diagnose
npm run dist
```

`test` 使用合成控件树和隔离数据，不连接设备。`smoke` 使用隐藏的 Electron 窗口检查六个页面与实际 IPC，截图在 `tmp/smoke/`。`diagnose` 只读取 ADB 设备、应用版本和无障碍服务状态，不连接、安装、启用或发送指令。

安装包输出在 `dist/`，构建缓存位于 `tmp/builder-cache/`。本地 Electron 已由 `npm ci` 安装，打包复用它。构建脚本处理旧版 Windows 工具包内不需要的 macOS 符号链接，不要求因此启用管理员权限。

桥接 APK 编译使用：

```powershell
powershell -File tools/syl-bridge/build.ps1 -Jdk '<JDK目录>' -BuildTools '<Android build-tools目录>' -AndroidJar '<android.jar路径>'
```

APK 的 `debug.keystore` 不提交。已有安装的更新需要保留相同签名；丢失签名时不能声称可直接覆盖升级。APK v2 使用私有结果文件、请求 ID 与原子写入，广播接收器仅允许 shell/system 权限。
