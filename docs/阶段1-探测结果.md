### ⚠️ ADB 三个坑（必须遵守）

1. **每个新 shell 会话都会杀掉并重启 adb server** → 设备列表丢失。
   **对策**：每条 adb 命令前都执行 `adb start-server && adb connect 127.0.0.1:5555`。
2. **Git Bash 会把 `/sdcard/xxx` 转成 Windows 路径**（`C:\Users\...\sdcard\xxx`）。
   **对策**：`export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"`。
3. 设备名优先用 `emulator-5554`，避免 `127.0.0.1:5555` 偶发 not found。

## 四、输入能力实测

| 测试 | 结果 |
|---|---|
| `input tap` 点输入框 | ✅ 正常 |
| `input text "hello123"` | ✅ **成功**（英文数字正常） |
| `input text "你好"` | ❌ **崩溃** `NullPointerException`（ADB 已知限制） |

### 结论：**必须安装 ADBKeyboard**

- 项目：`https://github.com/senzhk/ADBKeyBoard`（兼容 Andriod 高版本）
- 包名：`com.android.adbkeyboard`
- 用法：
  ```bash
  # 切换到 ADBKeyboard
  adb shell ime enable com.android.adbkeyboard/.AdbIME
  adb shell ime set com.android.adbkeyboard/.AdbIME
  # 发送 Unicode（Base64 编码）
  adb shell am broadcast -a ADB_INPUT_B64 --es msg "$(echo -n '你好' | base64)"
  # 用完切回原输入法
  adb shell ime set com.android.inputmethod.pinyin/.InputService
  ```

## 五、三条功能的实现映射（已确定）

### 功能 1：自动私聊（写作业）

原实现（CDP）→ Android 等价实现（ADB）：

| 原步骤 | Android 实现 |
|---|---|
| `piscesApi('/UI/Search/exactUser')` 查 uid | 私聊**不需要 uid**，直接走消息页会话 |
| `mod[mapping.text]({targetId, content})` 注入发送 | ① 点开对话 → ② 点 `input_message` → ③ ADBKeyboard 输中文 → ④ 点 `iv_send` |
| 轮询 history 验证 `messageUId` | dump `rc_message_list`，比对最后一条 `rc_text` 是否等于所发内容 |

**关键技术点**：
- 发送后 `rc_text` 的新消息气泡是**自己的**，可用 `iv_bubble_bg` 位置或「最后一条 `rc_text` 内容 == 发出内容」确认成功
- 输入框在发送后会自动清空，可作为成功信号之二

### 功能 2：自动欢迎

原实现：注入 `MutationObserver` 监听欢迎图标 `bg-linear-gradient-7DEDFF`。
Android 无 MutationObserver → **轮询 UI 树 + 差分**：

1. 定时（建议 1.5~2.5s）dump 当前界面
2. 解析出所有"可点击且带特定图标特征"的节点集合
3. 与上一次集合做差分，新出现的节点 → 命中欢迎按钮 → 点击
4. **难点**：欢迎按钮是 ImageView，`content-desc` 为空 → 需要**先用截图+人工标注**确定它的 resource-id 或稳定坐标规律

**待补充探测**：进入一个房间后 dump，找欢迎按钮的 id。

### 功能 3：自动打call

原实现：DOM 按文字/alt 找 `打call`。
Android 实现：进房间后 dump，找文字含"打call"/"call"的节点或对应 ImageView 点击。

**待补充探测**：进房间后 dump。

# 阶段 1.5 补充：房间页破解（无障碍桥接方案）

## 问题
房间页（`RoomPageActivity`）有大量持续动效（花瓣/星光/麦位动画），
系统 `uiautomator dump` **永远失败**：`ERROR: could not get idle state`
（关动画设置无效、`--compressed` 无效、连续重试 5 次全失败）。

## 解决方案：自建 AccessibilityService（`com.syl.bridge`）

原理：`AccessibilityService.getRootInActiveWindow()` **直接取节点树，不等 idle**。

### 通信链路
```
主机 Node.js
   ↓ adb shell am broadcast -a com.syl.bridge.CMD --es cmd dump -p com.syl.bridge
模拟器 无障碍服务(com.syl.bridge)
   ↓ 写 JSON 到应用私有目录(/data/data/com.syl.bridge/files/syl_ui.json)
主机 Node.js
   ↓ adb exec-out run-as com.syl.bridge cat files/syl_ui.json
拿到完整节点树(JSON)
```

关键设计：
- APK 设 **`android:debuggable="true"`** → 使 `run-as` 可用（非 root 也能读应用私有目录）
- 输出到 **应用内部私有目录**（`getFilesDir()`），避免 `/sdcard` 分区存储限制
- 支持指令：`ping` / `dump` / `tap`(by id) / `tapxy` / `text` / `clicktext` / `longclick`

### 工程位置
- 源码：`tools/syl-bridge/`
- 编译：`bash tools/syl-bridge/build.sh`（aapt2 + javac + d8 + apksigner 手工打包，无需 Android Studio）
- 产物：`tools/syl-bridge/syl-bridge.apk`（约 17KB）
- 依赖：build-tools r34 + platform-33 的 android.jar（已下载到 `tmp/`）

### 实测结果 ✅
| 页面 | uiautomator | 桥接服务 |
|---|---|---|
| 主界面/消息页 | ✅ 可用 | ✅ 可用 |
| **房间页** | ❌ 永远失败 | ✅ **104 节点成功** |
