# 推荐列表与作者分配

## 已确认规则

采用用户指定的图一蓝色徽章对应的财富等级（升级后颜色会变化）：数值≥54为高等级，<54为低等级；明确显示问号的等级默认高等级。另一徽章为魅力等级，独立保存，不与财富数值混合。年龄、麦位数字、靓号及昵称数字均不充当等级。

等级未读取成功不等于问号，单列“未识别”等待补查。隐藏等级在高等级组顶部明确标注；有数值用户在各组按等级降序。使用真实UID去重，最新观测决定分组，并保留来源索引。

## 使用路径

1. 实时贵宾位→采集公开资料，取得用户真实UID与等级。
2. 推荐列表→使用默认财富等级/54，或显式调整体系、阈值后保存刷新。
3. 选择分组，勾选用户、点击用户行或全选当前分组。
4. 填写1至2000个Unicode字符的推荐内容，点击“指定作者”。
5. 作者分配记录显示推荐内容、作者名称、UID、时间及采用的阈值。重启后保留。

用户只提供昵称、未能核验真实UID时不能直接指定作者。指定作者是本地职责分配，不产生新的私信发送。

## 数据与实现

- 采集数据：用户数据目录 `records-v2.json`，新增 `wealthLevel`、`charmLevel`。有效值为非负整数或明确问号 `?`；未读到新值保留已有可信等级。
- 徽章读取：优先当前可见显式等级控件；图像徽章采用限定区域的数字字形匹配与问号校验，Windows内置OCR作为缺字段备用。截图后核对UID、昵称与布局。数字资产仅包含字形掩码，不包含用户头像或UID。可信单字段结果不会因另一个字段的OCR失败而丢失。
- 分组：`src/recommendation-policy.cjs`。默认财富54；支持独立体系与显式非负整数阈值。
- 分配：用户数据目录 `recommendations-v1.json`；保存内容、作者UID与用户快照、分类字段、阈值及时间。原子保存和备份恢复；损坏不静默覆盖。请求ID幂等防止响应丢失后重复分配。
- 接口：`api.recommendation.list(options)`、`assign(request)`、`assignments()`；沿用现有preload/IPC边界，不直接从页面访问文件。
- 界面：`design/js/recommendation-view.js`、`design/css/recommendation-view.css`，沿用导航和暗色样式。
- 原分类导出仍可用：`npm run classify -- --level-field wealthLevel`。两个等级体系同时出现时必须明确选体系。

## 本地运行问题及修复

| 问题位置 | 触发条件 | 影响 | 处理 |
| --- | --- | --- | --- |
| 推荐页空状态样式 | 有用户且元素hidden=true，但通用field-hint的display:flex覆盖隐藏 | 轻微：表格同时出现空列表提示 | 增加局部hidden样式；实际Electron检查computedStyle为none |
| 等级图像识别 | 系统OCR把???识别成000 | 严重：隐藏等级会被误归低等级 | 在限定徽章区域校验重复问号符号，明确问号优先；数值和隐藏等级分别验证 |
| 资料卡等级读取 | 离屏/禁用旧控件，或OCR覆盖显式控件数字 | 一般：错误分类 | 只接受当前可见同身份控件，显式数值优先，截图后复核身份和布局 |
| 首页房间导航 | 首页滚动后推荐区域离屏；真实mRecyclerView暴露为GridView | 一般：持续等待，无法采集 | 依据可见首页标签、导航和容器内房间卡确认首页，兼容GridView；新增实际结构回归 |
| 系统文字识别 | 当前系统语言包漏读71，或将119拆为多个词 | 一般：等级漏检 | 小型数字字形匹配优先，无新增第三方依赖；不确定值保持未识别 |
| 推荐身份过滤 | 非布尔uidReal标记、数值UID或混杂字符串 | 严重：可能将无效身份用于作者分配 | 仅真实数字字符串UID及true/历史未标记记录；回归验证拒绝 |
| 作者重复提交 | 双击按钮或响应丢失后重试 | 一般：重复职责记录 | 前端pending互斥、重试复用requestId；后端幂等及冲突拒绝 |
| 存储通知（上一轮修复一并提交） | 数据已落盘但界面订阅抛错 | 严重：误报保存失败 | 安全通知、事件类型与堆栈日志，落盘异常仍正常上报 |
| 黑名单配置（上一轮修复一并提交） | UID超过32位 | 一般：保存与任务启动规则不一致 | 统一配置与任务校验 |
