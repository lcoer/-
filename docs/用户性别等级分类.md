# 用户性别与等级组合分类

## 数据依据

输入是双鱼助手持久化数据集 `records-v2.json`，格式为 `{schemaVersion:2,records:[...]}`，默认路径 `%APPDATA%/shuangyu-assistant/records-v2.json`；设置 `SYBL_USER_DATA_DIR` 时使用该目录。不是云端数据库表。

性别字段为 `sex`：male/男/m → 男，female/女/f → 女，other/其他 → 其他，缺失或无法识别 → 未知。未知不算“其他”。当前采集数据没有 VIP 或用户等级字段，不能把麦位分值、房间热度或私信贡献等级拒绝提示当成用户等级。

等级优先由 `--level-field` 显式指定；未指定时检查 vipLevel、userLevel、level、vip_level、user_level。仅发现一种有值字段时使用该字段；缺失时归未知，同时存在多种等级时提示用户选择，不混合 VIP 和用户等级。现有等级值逐值分类，例如 0、1、2 或 VIP1；不擅自定义项目没有提供的等级阈值。

## 执行方式

```powershell
# 读取当前已收集数据，生成一次分类导出
npm run classify

# 仅统计上海日期 2026-10-10 的观测
npm run classify -- --date 2026-10-10

# 数据已含 VIP 等级时明确选择该体系；原数据缺少此字段仍归未知
npm run classify -- --input "D:\数据\records-v2.json" --level-field vipLevel
```

代码直接调用：

```javascript
const {classifyUsers} = require('./src/user-classification.cjs');
const result = classifyUsers(records, {genderField:'sex', levelField:'userLevel'});
```

实现位置：`src/user-classification.cjs`；命令入口：`scripts/classify-users.cjs`。分类不修改原始文件、现有 UI、采集或私信流程。

## 统计口径与追溯

对筛选后的观测，同一真实 UID 只计一个用户，取 lastSeenAt（缺省取 ts）最新的一条确定其性别与等级组合。时间相同时以数据集靠后的记录为准；历史观测全部保留在来源快照，并通过 sourceRecordIndexes 引用。

默认统计 source=room 的采集记录。仅昵称占位线索按 source、roomCode/room、占位 ID 分开归组；它们不能证明是真实独立用户，单列 unverifiedCount，不计入 userCount。演示数据始终排除。等级未知使用 unknown，等级 0 保留为 "0"，不会与未知合并。

每个实际出现的组合包含：

- gender、level：标准化分类值；等级依据字段同时记在 fields.level。
- userCount：可用数字 UID 的唯一用户数。
- unverifiedCount：尚未核验的独立线索数。
- observationCount：该组合涉及的原始观测条数。
- userIds：该组合的真实用户 ID。
- detailIndexes：索引到 details，每条明细含 original 原始最新记录及所有 sourceRecordIndexes（0 起始）。

用户在历史上改变等级/性别时，默认只出现在最新组合；用 --date 可限定观测日期。此处的“真实 UID”依据数据集原有 uidReal 标记及数字格式，分类不再次进行设备身份核验。

## 存储方式

默认新增版本目录 `exports/user-classification/<UTC生成时间>/`：

1. `classification.json`：字段依据、来源路径及 SHA256、筛选口径、组合数量、用户 ID 与可追溯明细。
2. `summary.csv`：组合汇总，含 gender、level、userCount、unverifiedCount、observationCount；UTF-8 BOM，可直接用 Excel 打开。
3. `source-records.json`：输入文件的逐字节快照；即使日常采集继续更新 live 文件，旧分类仍可按原始行索引追溯。

--output 可指定导出目录；来源快照使用排他创建，已有同名快照时拒绝覆盖，建议每次使用新目录。
