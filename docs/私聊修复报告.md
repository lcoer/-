# 自动私聊修复：1.3.0

截图报错 `CONVERSATION_NOT_FOUND(音-8v)`，目标 ID 为 888188。旧实现仅在消息列表按昵称查找已存在的会话；采集新用户后没有建立会话的路径，因而无法私聊。

现在按 UID 搜索用户，切换用户标签，要求完整数字 ID 精确匹配，进入主页核对后打开 iv_chat，再查看聊天对象主页复核 ID，最后按文案模式输入和发送。身份含糊、页面改变、未找到用户或任务取消时停止该操作，不选第一个模糊结果。

完整主页实测提供 tv_nice_num、tv_nickname、iv_copy、iv_follow、iv_chat。这一数字仅在完整主页标记共同成立时接受；房间公开卡片仍要求原有 tv_user_code 证据。

同时修复：文案输入框未新增的草稿在保存/启动时收录，保存失败不启动，确认框预览指定文案或随机池；规则恢复已保存的来源、日期和小时；前台 App 不重复启动 LaunchActivity，以免停在启动画面。

实机导航验证：UID 888188，昵称音-8v，搜索→主页→首次聊天→二次主页核对→返回聊天耗时 33.336 秒。中文文案“你好呀，很高兴认识你~”通过 sendPrivateMessage 完整填入，证据 inputMatched=true、expectedUid=actualUid=888188，在 onBeforeSend 前置回调主动中止，未点击发送，验证草稿已清空。发送和确认分支由模拟设备集成测试验证，未向真实用户发送测试消息。

独立审查发现并修复两个边界：聊天内容提及房间密码不能触发房间退出；保存发送意图后需再次读取聊天、核对正文并获取当前发送坐标。保留待确认停止、黑名单、今日去重和设备独占策略。

最终回归：166 项测试通过；78 个源码文件及129个 HTML ID 检查通过。Windows 桌面版本和安装包为1.3.0，桌面原有快捷方式继续使用同一程序路径。
